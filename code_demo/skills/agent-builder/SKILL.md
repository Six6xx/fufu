# 代理构建器（Agent Builder）

为任意领域构建 AI 代理——客户服务、研究、运营、创意工作或专业业务流程。

## 核心理念

> **模型本身已经知道如何成为代理。你的任务是别挡它的路。**

代理并非复杂的工程，而是一个简单的循环，邀请模型采取行动：

```
循环：
  模型看到：上下文 + 可用能力
  模型决定：执行动作 或 返回回复
  若执行动作：调用能力，添加结果，继续循环
  若返回回复：向用户返回结果
```

**仅此而已。** 魔法不在代码中——而在模型里。你的代码只是提供机会。

## 三大要素

### 1. 能力（它能做什么？）

代理可执行的原子操作：搜索、读取、创建、发送、查询、修改。

**设计原则**：从 3–5 个能力开始。仅当代理因缺少某项能力而持续失败时，才添加更多。

### 2. 知识（它知道什么？）

按需注入的领域专业知识：政策、工作流、最佳实践、模式定义等。

**设计原则**：让知识可用，但不强制加载。在相关时加载，而非一开始就塞入。

### 3. 上下文（发生了什么？）

对话历史——将各个动作串联成连贯行为的线索。

**设计原则**：上下文极其宝贵。隔离会产生噪音的子任务，截断冗长输出，保护清晰度。

## 代理设计思维

在构建前，请明确：

- **目标**：这个代理应完成什么？
- **领域**：它在哪个世界中运行？（客户服务、研究、运营、创意……）
- **能力**：哪 3–5 个动作是必需的？
- **知识**：它需要访问哪些专业知识？
- **信任**：哪些决策可以交给模型？

**关键**：信任模型。不要过度工程化，不要预先规定工作流。赋予其能力，让它自行推理。

## 芙芙 AI 伴侣的代理架构

本项目采用以下架构模式，可作为参考：

```
Agent 主循环 (agent_loop)
├── SystemPromptBuilder — 动态组装系统提示词（工具 + 技能 + 记忆）
├── 工具池 — 原生工具(bash/read/write/edit) + 代理工具 + MCP工具
├── CapabilityPermissionGate — 统一权限门控
├── MCPToolRouter — MCP 工具路由 (mcp__server__tool)
├── SkillRegistry — 按需加载领域知识
├── MemoryManager — 跨会话记忆注入
└── 流式输出 — token_callback + tool_callback
```

**工具类型**：
- 原生工具：`bash` / `read_file` / `write_file` / `edit_file`
- 代理工具：`send_message` / `read_inbox` / `list_teammates` / `list_tasks` / `claim_task`
- 技能工具：`list_skills` / `load_skill`
- 定时调度：`cron_create` / `cron_delete` / `cron_list`
- MCP 工具：`mcp__{server}__{tool}`（运行时动态注册）

## 渐进式复杂性

从简单开始。仅当实际使用暴露出需求时，才增加复杂性：

| 层级 | 添加内容 | 何时添加 |
|------|----------|----------|
| 基础 | 3–5 项能力 | 始终从此开始 |
| 规划 | 进度跟踪 | 多步骤任务失去连贯性时 |
| 子代理 | 隔离子代理 | 探索过程污染上下文时 |
| 技能 | 按需知识 | 需要领域专业知识时 |

**大多数代理永远不需要超过第 2 层。**

## 领域示例

**商业**：CRM 查询、邮件、日历、审批
**研究**：数据库搜索、文档分析、引用生成
**运营**：监控、工单、通知、升级处理
**创意**：资产生成、编辑、协作、审阅

该模式具有普适性，唯一变化的是能力。

## 核心原则

1. **模型即代理** —— 代码只负责运行循环
2. **能力赋能** —— 它能做什么
3. **知识引导** —— 它知道如何做
4. **约束聚焦** —— 限制带来清晰
5. **信任释放** —— 让模型自行推理
6. **迭代揭示** —— 从极简开始，根据使用演进

## 反模式

| 反模式 | 问题 | 解决方案 |
|--------|------|----------|
| 过度工程 | 在需求出现前就复杂化 | 从简单开始 |
| 能力过多 | 导致模型困惑 | 初始仅 3–5 个 |
| 固定工作流 | 无法灵活适应 | 让模型自行决定 |
| 知识前置加载 | 上下文膨胀 | 按需加载 |
| 微观管理 | 削弱智能表现 | 信任模型 |

## 代理思维模式

**从**："我如何让系统做 X？"
**到**："我如何让模型有能力做 X？"

**从**："这个任务的工作流是什么？"
**到**："哪些能力有助于完成此任务？"

最好的代理代码几乎平淡无奇：简单循环、清晰能力、干净上下文。魔法不在代码中。

**赋予模型能力和知识，相信它能搞定其余一切。**
