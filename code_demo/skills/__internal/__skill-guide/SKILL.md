# 技能进化指导

## auto_create 判断

自动创建技能需要同时满足以下条件：

### 触发条件
- 工具调用序列 **≥ 5 步**的复杂任务已完成
- 用户可能**重复执行**的工作流（非一次性操作）
- 已有相似技能**覆盖度 < 70%** 时才创建

### 不创建的情况
- 简单的 2-3 步操作（如「读文件 → 改一行」）
- 一次性调试任务
- 已有技能能覆盖 70% 以上步骤
- 用户明确表示不需要

### 创建流程
1. 分析工具调用序列，提取关键步骤
2. 检查已有技能的覆盖度（MinHash 相似度）
3. 覆盖度 < 70% → 生成 SKILL.md
4. 新技能默认 **未锁定**，鼓励用户 review

## 合并推荐

### 合并条件
- MinHash Jaccard 相似度 **> 0.6** 时推荐合并
- 仅推荐**未锁定的技能**
- 合并后保留较高 `usage_count` 的技能作为基础

### 合并流程
1. 检测到新技能与已有技能相似度 > 0.6
2. 评估两个技能的覆盖范围和 usage_count
3. 以 usage_count 更高的为基础，融入另一技能的独特步骤
4. 合并后保留一个 SKILL.md，另一个移入"已被学习"区域
5. 通知用户合并结果

## 锁定机制

### 用户锁定的技能
- 视为**「稳定版」**，不建议修改
- 锁定标记在 frontmatter 中：`locked: true`
- 合并推荐时跳过已锁定技能
- 如果必须修改锁定技能，先征求用户同意

### 未锁定的技能
- 自动创建的技能默认未锁定
- 鼓励用户 review 后决定是否锁定
- 可参与合并推荐流程

## 冲突处理

### 内部技能冲突
- `__internal/` 下的技能标记 `locked: true`
- 新创建的 skill 与内部 skill 冲突时 → 自动触发合并
- 合并方向：内部技能为基础，融入新技能的增量部分
- 合并后原 skill 下线到"已被学习"区域

### 外部技能冲突
- 两个用户技能相似度 > 0.6 时，推荐合并
- 不自动执行合并，只提出建议
- 用户确认后才执行合并操作

## 技能格式

```yaml
---
name: 技能名称
description: "一句话描述"
source: manual | auto
locked: false
created_at: 日期
updated_at: 日期
usage_count: 0
---
```

## 技能存储位置

- 内置隐藏技能：`skills/__internal/`
- 用户可见技能：`skills/`（非 `__internal` 子目录）
- 技能注册表由 `SkillRegistry` 管理
