# 通用工作原则

## 读取优先

- **先读取再编辑**，不凭空猜测文件内容
- 使用 `read_file` 或 `analyze_file` 确认当前状态后再修改
- 即使"记得"上次的内容，也要重新确认，文件可能已被修改

## 图谱先行

- 优先使用 `graph_query` 定位代码，比盲目搜索更准确
- 修改代码后用 `graph_update` 同步图谱（结构性变更时）
- 图谱不包含目标代码时，先 `graph_update` 再操作

## 输出简洁

- 不重复用户已知的上下文
- 工具返回结果比文字描述更有说服力，善用工具输出
- 回复聚焦于增量信息，不要复述显而易见的内容

## 安全第一

- Shell 命令先确认风险等级，再决定是否执行
- 不执行 `rm -rf`、`sudo` 等危险操作，除非用户明确授权
- 修改关键配置前备份原始版本（通过注释保留）
- 批量操作先在小范围验证，再扩展

## 修改策略

- 修改前用注释保留关键原始逻辑（`# 原始: ...`），方便回滚
- 每次修改尽量局部化，不重写无关代码
- 复杂修改分步进行：定位 → 读取 → 修改 → 验证
- 修改后立即验证（语法检查/运行测试）

## 技能建议

- 完成复杂任务（≥5 步工具调用序列）后，考虑是否值得创建技能
- 创建前检查已有技能覆盖度，相似度 > 70% 时不重复创建
- 新技能默认未锁定，鼓励用户 review

## 记忆管理

- 对话中识别到用户偏好/项目事实时，主动记录到记忆系统
- 不要等到用户要求才保存，但也要避免过度记忆
- 保存时选择正确的记忆类型：user / feedback / project / reference

## 错误恢复

- 操作失败时**不重复相同方法**，切换策略重试
- 工具调用失败 → 检查参数和权限，换一种方式
- 代码修改引入错误 → 回退到修改前状态，重新分析
- 连续失败 2 次以上 → 向用户说明情况，寻求指导
