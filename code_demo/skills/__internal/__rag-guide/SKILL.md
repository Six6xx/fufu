# RAG 检索指导

## 何时使用 RAG

- 用户提问涉及**项目知识/历史决策**（如「为什么选择这个架构？」）
- 需要**跨文件的语义相关信息**（如「哪里处理了类似的错误模式？」）
- 查找**代码注释/文档中的领域知识**
- 图谱无法覆盖的模糊/语义级查询

## 检索策略选择

### 精确关键词匹配 → BM25 / FTS5
- 知道具体关键词或术语时使用
- 例：查找所有 `SQLAlchemy` 相关代码
- 特点：速度快，精确匹配，不依赖语义理解
- 适用场景：已知术语搜索、错误信息查找

### 语义相似度 → 向量检索
- 用自然语言描述需求时使用
- 例：「处理用户认证的逻辑在哪？」
- 特点：理解查询意图，匹配语义相近的内容
- 适用场景：概念性查询、模糊描述匹配

### 综合需求 → 混合检索 + RRF 重排序
- 需要兼顾精确匹配和语义理解时使用
- 混合 BM25 + 向量检索结果
- RRF (Reciprocal Rank Fusion) 重排序融合两种结果
- 适用场景：大多数实际查询

## 结果引用格式

- 引用时标注**来源文件和行号**
- 例：「根据 `core/server.py#L45-L52` 的实现...」
- **不要大段复制检索结果**，提炼要点
- 如果多个来源有相同信息，合并引用
- 检索结果可能过时，与实际代码交叉验证

## DocumentIndexer 使用

### 增量索引触发
- 新增文档后触发增量索引
- 代码变更后的相关文档需要重新索引
- 不要手动触发全量索引（开销大），除非索引损坏

### 索引范围
- 代码文件（.py, .js, .ts 等）
- 配置文件（.json, .yaml, .toml）
- 文档文件（.md, .rst, .txt）
- 不索引：二进制文件、缓存目录、node_modules

## RAG 与图谱的协作

- **图谱擅长**：结构化关系查询（谁调用了谁、依赖链）
- **RAG 擅长**：语义级内容检索（这段代码做什么、为什么这样设计）
- 复杂分析时两者结合：图谱定位结构，RAG 深入语义
- 不要只用一种，根据问题性质选择

## RAG 模块位置

- 核心模块在 `rag/` 目录下
- `hybrid_retriever.py` — 混合检索 + RRF
- `vector_store.py` — 向量存储
- `query_router.py` — 查询路由（选择检索策略）
- `reranker.py` — 结果重排序
- `document_indexer.py` — 文档索引器
