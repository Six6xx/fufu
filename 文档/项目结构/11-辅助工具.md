## 二、safe_path — 路径安全

### 威胁模型

LLM 可能生成的恶意路径：
```
../../etc/passwd           ← 路径遍历
./symlink_to_secrets/..    ← 符号链接逃逸
```

### 两层防护

```python
def safe_path(p: str, workdir: Path | None = None) -> Path:
    base = (workdir or WORKDIR).resolve()
    path = (base / p).resolve()
    
    # 第 1 层：路径遍历检查
    if not path.is_relative_to(base):
        raise ValueError(f"路径 {p} 不在工作目录内")
    
    # 第 2 层：符号链接检查（逐段）
    check_path = workdir or WORKDIR
    for part in Path(p).parts:
        check_path = check_path / part
        if check_path.is_symlink():
            target = check_path.resolve()
            if not target.is_relative_to(base):
                raise ValueError(f"符号链接 {check_path} 指向工作目录之外")
    
    return path
```

**`workdir` 参数**：允许动态指定基准目录，用于支持 per-session 工作空间。为 `None` 时回退到全局 `WORKDIR`（即 `DEFAULT_WORKDIR`）。Agent 调用原生工具时传入 `workdir=self.workdir`，runner.py 再传给 `safe_path()`。

**为什么两层？**
- 第 1 层：`resolve()` 解析所有 `..` 和符号链接后检查，能抓住简单遍历
- 第 2 层：逐段检查符号链接，防止 `resolve()` 之后的符号链接指向外部

## 三、persist_large_output — 大输出持久化

### 问题

工具输出可能非常大（如 `find /` 返回几十万行），直接放入对话上下文会：
1. 浪费 token
2. 超出上下文限制
3. 影响 LLM 推理质量

### 解决方案

```python
def persist_large_output(tool_use_id: str, output: str) -> str:
    if len(output) <= PERSIST_THRESHOLD:  # 30K 字符
        return output  # 不够大，直接返回
    
    # 保存完整输出到文件
    file_path = TOOL_RESULTS_DIR / f"{tool_use_id}.txt"
    file_path.parent.mkdir(parents=True, exist_ok=True)
    file_path.write_text(output, encoding="utf-8")
    
    # 返回摘要 + 文件引用
    preview = output[:PREVIEW_CHARS]  # 前 2000 字符
    return f"""<large-output file="{file_path}">
{preview}
... (已截断，完整输出见上述文件)
</large-output>"""
```

## 四、SkillRegistry — 技能注册表

### 什么是技能？

技能是预定义的操作指南（Markdown 文件），告诉 Agent 如何完成特定任务。例如：
- `code_review.md`：代码审查检查清单
- `deploy.md`：部署流程指南
- `testing.md`：测试编写规范

### 存储格式

每个技能是一个 `SKILL.md` 文件，使用 YAML frontmatter：

```markdown
---
name: code_review
description: 代码审查检查清单和最佳实践
---

# 代码审查指南

## 检查清单
1. 类型安全
2. 错误处理
3. 性能考量
...
```

### 目录结构

```
ai_output/.skills/
├── code_review/
│   └── SKILL.md
├── deploy/
│   └── SKILL.md
└── testing/
    └── SKILL.md
```

### API

```python
class SkillRegistry:
    def _load_all(self):
        # 递归搜索 **/ SKILL.md
        # 解析 frontmatter → SkillManifest
    
    def describe_available(self) -> str:
        # 返回可用技能列表 (用于系统提示词)
        # "- code_review: 代码审查检查清单"
        # "- deploy: 部署流程指南"
    
    def load_full_text(self, name: str) -> str:
        # 加载完整技能内容
        # 返回 <skill>...</skill> XML 包裹的文本
        # 供 Agent 通过 load_skill 工具使用
```

### 使用流程

```
Agent 收到 "帮我做代码审查"
    │
    ▼
Agent 调用 list_skills() → "code_review: 代码审查检查清单"
    │
    ▼
Agent 调用 load_skill("code_review") → 完整技能内容
    │
    ▼
技能内容注入对话上下文
    │
    ▼
Agent 按照技能指南执行代码审查
```

## 六、BashSecurityValidator — Bash 安全检测

### 检测模式

```python
VALIDATORS = [
    ("shell_metachar", r"[;&|`$]"),          # Shell 元字符
    ("sudo", r"\bsudo\b"),                     # 权限提升
    ("rm_rf", r"\brm\s+(-[a-zA-Z]*)?r"),       # 递归删除
    ("cmd_substitution", r"\$\("),              # 命令替换
    ("ifs_injection", r"\bIFS\s*="),           # IFS 操纵
]
```

### API

```python
class BashSecurityValidator:
    def validate(self, command: str) -> list:
        # 返回 [(名称, 模式), ...] 失败列表
        # 空列表 = 安全
    
    def is_safe(self, command: str) -> bool:
        # 便捷方法: len(validate()) == 0
    
    def describe_failures(self, command: str) -> str:
        # 人类可读的失败描述
```

### 使用位置

```python
# WorktreeManager.run() 中
if not bash_validator.is_safe(command):
    return bash_validator.describe_failures(command)

# PermissionManager.check() 中
if tool_name == "bash":
    failures = bash_validator.validate(command)
    severe = {"sudo", "rm_rf"}
    if any(f[0] in severe for f in failures):
        return {"behavior": "deny", ...}
```

### 示例

```python
v = BashSecurityValidator()

v.is_safe("ls -la")                    # True
v.is_safe("cat file.txt")              # True

v.is_safe("sudo rm -rf /")            # False
v.validate("sudo rm -rf /")
# → [("sudo", "\\bsudo\\b"), ("rm_rf", "\\brm\\s+...")]

v.is_safe("echo $(whoami)")           # False
v.validate("echo $(whoami)")
# → [("cmd_substitution", "\\$\\(")]
```

### 模型类型推断

```python
def _infer_model_type(model_name: str) -> str:
    """从模型名推断类型: vl/vision/image/video → vlm, 否则 → llm"""
    import re
    if re.search(r'vl|vision|image|video', model_name, re.IGNORECASE):
        return "vlm"
    return "llm"
```

### API Key 脱敏

```python
def _mask_api_key(key: str) -> str:
    """sk-abcdef → sk-****cdef (显示前3+后4位)"""
    if not key or len(key) <= 7:
        return "****"
    return f"{key[:3]}****{key[-4:]}"
```

## 八、VoiceProviderManager — 语音供应商管理 (TTS/ASR)

### 用途

管理 TTS 和 ASR 远程服务的配置（名称、URL、API Key、高级配置），支持运行时切换远程/本地引擎。数据持久化到 `ai_configuration/voice_providers.json`。与 `ProviderManager`（LLM）平行设计，但字段独立。

### JSON 结构

```json
{
    "tts_providers": [
        {
            "id": "tts_xxxx",
            "name": "GPU 服务器",
            "url": "http://192.168.1.100:9876",
            "api_key": "",
            "provider_type": "remote",
            "config": {
                "default_prompt_text": "You are a helpful assistant.<|endofprompt|>...",
                "sample_rate": 22050
            }
        }
    ],
    "asr_providers": [],
    "active_tts_provider_id": "tts_xxxx",
    "active_asr_provider_id": null,
    "tts_fallback_to_local": true
}
```

### API

```python
class VoiceProviderManager:
    def __init__(self):
```
