## 二、原生工具 (native/)

原生工具分为两组：**基础工具**（runner.py 中的 4 个文件/Shell 操作）和**图谱工具**（graph_tools.py 中的 3 个 AST 分析工具）。

### 基础工具 (runner.py)

### run_bash

```python
def run_bash(command: str, workdir=None) -> str:
    """执行 shell 命令"""
    result = subprocess.run(command, shell=True, capture_output=True,
                            timeout=120, cwd=workdir)
    return (safe_decode(stdout) + safe_decode(stderr)).strip()
```

**关键细节**：
- `timeout=120` 秒（从 `BASH_TIMEOUT` 配置）
- `workdir` 参数：指定 shell 命令的工作目录（`cwd=workdir`），由 Agent 传入 `self.workdir`
- 安全解码：UTF-8 → GBK → ignore（兼容 Windows 中文输出）
- 输出截断：`[:MAX_OUTPUT_CHARS]`（500K 字符）

### run_read

```python
def run_read(path: str, limit: int = None, full_context=False, workdir=None) -> str:
    """读取文件"""
    text = safe_path(path, workdir=workdir).read_text(encoding="utf-8")

```

**关键细节**：
- `safe_path(path, workdir=workdir)` 在工作空间内检查路径遍历攻击（见辅助工具文档）
- 支持 `limit` 参数限制行数

### run_write

```python
def run_write(path: str, content: str, workdir=None) -> str:
    """写入文件"""
    fp = safe_path(path, workdir=workdir)
    fp.parent.mkdir(parents=True, exist_ok=True)  # 自动创建目录
    fp.write_text(content)
```

### run_edit

```python
def run_edit(path: str, old_text: str, new_text: str, workdir=None) -> str:
    """替换文件中的字符串（仅首次出现）"""
    fp = safe_path(path, workdir=workdir)
    content = fp.read_text()
    fp.write_text(content.replace(old_text, new_text, 1))  # count=1
```

**workdir 参数**：所有 4 个执行器均接受 `workdir` 参数（默认为 `None`，回退到全局 `WORKDIR`）。Agent 的 `execute_tool()` 方法在调用原生工具时注入 `workdir=self.workdir`，确保文件操作和 shell 命令在当前会话的工作空间内执行。

```python
def run_graph_update(path: str = ".", workdir=None) -> str:
    """增量更新项目知识图谱（AST 提取，无 LLM 成本）。

    合并到已有的 graph.json 中。若图谱不存在则从零构建。
    """
    from graphify.extract import collect_files, extract
    from graphify.build import build_merge
    from graphify.cluster import cluster
    from graphify.export import to_json

    files = collect_files(Path(resolved_path))
    chunks = [extract(files)]
    G = build_merge(chunks, str(graph_path))

    to_json(G, communities, str(graph_path))
    return f"图谱已更新: {G.number_of_nodes()} 节点, {G.number_of_edges()} 边"
```

## 三、MCP 协议 (mcp/)

### 什么是 MCP？

MCP (Model Context Protocol) 让外部进程暴露工具给 Agent，就像插件系统：

```
Agent ←──JSON-RPC──→ MCP Server 进程
           stdio
```

### MCPClient — 单个服务器连接

```python
class MCPClient:
    def __init__(self, server_name, command, args, env):
        # server_name: 服务器标识 (用于工具前缀)
        # command: 启动命令 (如 "node")
        # args: 命令参数 (如 ["server.js"])
    
    def connect(self) -> bool:
        # 1. Popen 启动子进程
        # 2. 发送 initialize 请求
        # 3. 等待响应
        # 4. 发送 initialized 通知
    
    def list_tools(self) -> list:
        # 发送 tools/list → 获取可用工具列表
    
    def call_tool(self, tool_name, arguments) -> str:
        # 发送 tools/call → 执行工具 → 返回结果文本
    
    def disconnect(self):
        # 发送 shutdown → terminate → wait(5s) → kill
    
    def get_agent_tools(self) -> list:
        # 返回带前缀的工具定义
        # 格式：mcp__{server_name}__{tool_name}
```

### JSON-RPC 通信

```
→ {"jsonrpc": "2.0", "id": 1, "method": "initialize", "params": {...}}
← {"jsonrpc": "2.0", "id": 1, "result": {...}}
→ {"jsonrpc": "2.0", "method": "notifications/initialized"}
→ {"jsonrpc": "2.0", "id": 2, "method": "tools/list", "params": {}}
← {"jsonrpc": "2.0", "id": 2, "result": {"tools": [...]}}
```

**超时机制**：使用 `select.select()` 实现 30 秒超时读取，防止服务器挂起时永久阻塞。

### 完整流程

```
Agent 启动
    │
    ▼
PluginLoader.scan()
    │ 扫描 .claude-plugin/plugin.json
    ▼
PluginLoader.get_mcp_servers()
    │ 返回 {plugin__server: {command, args, env}}
    ▼
对每个服务器：
    MCPClient(server_name, command, args)
    │
    ├── connect()     ← Popen + initialize 握手
    ├── list_tools()  ← 获取工具列表
    └── router.register_client(client)
    
工具调用时：
    execute_tool("mcp__github__create_issue", {...})
    │
    ▼
router.is_mcp_tool() → True
    │
    ▼
router.call()
    │ 解析 server="github", tool="create_issue"
    │ 找到对应 MCPClient
    ▼
client.call_tool("create_issue", {...})
    │ JSON-RPC: tools/call
    ▼
返回结果文本
```

## 四、权限系统

### CapabilityPermissionGate (permission.py)

**统一权限门控**，同时处理原生工具和 MCP 工具：

```python
class CapabilityPermissionGate:
    def normalize(self, tool_name, tool_input) -> dict:
        # 分类工具意图：
        # source: "native" | "mcp"
        # server: 服务器名 (MCP) | "" (native)
        # tool: 工具名
        # risk: "read" | "write" | "high"
    
    def check(self, tool_name, tool_input) -> dict:
        # 返回 {"behavior": "allow"|"deny"|"ask", "intent": {...}}
        # 基于 mode 和 risk 判断
    
    def ask_user(self, intent, tool_input) -> bool:
        # 交互式确认提示
```

**风险分类**：

| 风险级别 | 判定条件 | 示例 |
|---------|---------|------|
| `read` | 工具名以 read_/list_/get_ 开头 | read_file, bash_readonly |
| `high` | 工具名匹配 HIGH_RISK_PREFIXES | bash (写操作) |
| `write` | 其他 | write_file, edit_file |

**危险模式**（`DANGEROUS_PATTERNS`）：
```python
["rm -rf", "sudo", "curl |", "wget |", "eval(", "exec(", ...]
```

### PermissionManager (permission_manager.py)

**高级权限管道**，基于规则链的决策：

```
check(tool_name, tool_input)
    │
    ├── Step 0: BashSecurityValidator (仅 bash 工具)
    │   └── 严重模式 (sudo, rm_rf) → 直接 deny
    │
    ├── Step 1: 拒绝规则遍历
    │   └── 匹配 → deny
    │
    ├── Step 2: 模式检查
    │   ├── plan 模式：写操作 deny，读操作 allow
    │   └── auto 模式：读操作 allow，写操作继续
    │
    ├── Step 3: 允许规则遍历
    │   └── 匹配 → allow
    │
    └── Step 4: 询问用户
        └── 返回 ask
```

**规则格式**：
```python
DEFAULT_RULES = [
    {"tool": "bash", "content": "rm -rf /", "behavior": "deny"},
    {"tool": "bash", "content": "sudo *", "behavior": "deny"},
    {"tool": "read_file", "path": "*", "behavior": "allow"},
]
```

**熔断机制**：连续 3 次拒绝后提示用户切换到 plan 模式。

**always 记忆**：用户选择 `always` 时，自动添加永久允许规则。
