## 二、MemoryManager — 记忆管理

### 存储结构

```
ai_output/memory/
├── MEMORY.md                  ← 索引文件 (≤200 行)
├── user_preferences.md        ← 用户偏好记忆

├── feedback_code_style.md     ← 代码风格反馈
└── reference_api_docs.md      ← API 文档引用
```

### 单条记忆格式

每个记忆文件使用 YAML frontmatter：

```markdown
---
name: user_preferences
description: 用户偏好使用 TypeScript 而非 JavaScript
type: user
---
用户多次表示偏好 TypeScript，所有新项目应默认使用 .ts 文件。
在代码审查中，用户要求类型注解必须完整。
```

### 记忆类型

| type | 含义 | 示例 |
|------|------|------|
| `user` | 用户个人信息 | 角色、技能水平、工作习惯 |
| `feedback` | 用户反馈 | 代码风格偏好、交互方式 |
| `project` | 项目上下文 | 技术栈、架构决策、进度 |
| `reference` | 外部引用 | API 文档链接、参考资料 |
| `skill_learned` | 学习到的技能 | 工具调用序列、操作流程 |
| `mistake` | 犯错记录 | 踩坑经验、错误模式 |

### 索引文件 (MEMORY.md)

自动生成的紧凑索引，始终加载到上下文中：

```markdown
# Memory Index

- user_preferences: 用户偏好使用 TypeScript [user]
- project_context: 当前项目使用 React + FastAPI [project]
- feedback_code_style: 偏好函数式编程风格 [feedback]
- reference_api_docs: DashScope API 文档位置 [reference]
```

**硬性限制**：最多 `MAX_INDEX_LINES = 200` 行。

### frontmatter 解析

```python
def _parse_frontmatter(self, text: str) -> dict | None:
    match = re.match(r"^---\s*\n(.*?)\n---\s*\n(.*)", text, re.DOTALL)
    if not match:
        return None
    header, body = match.group(1), match.group(2)
    result = {"content": body.strip()}
    for line in header.splitlines():
        if ":" in line:
            key, _, value = line.partition(":")
            result[key.strip()] = value.strip()
    return result
```

简单的 `key: value` 解析，不依赖 YAML 库。

## 三、DreamConsolidator — 记忆整合

### 为什么需要整合？

记忆库会随时间增长，可能出现：
- 重复的记忆（同一条信息被多次保存）
- 过时的记忆（项目已经变更）
- 碎片化的记忆（同一主题分散在多个文件）

DreamConsolidator 在会话间隙自动整合，类似人类的"梦境整理"。

### 7 重门控检查

整合前必须通过所有条件：

```
should_consolidate() → (can_run, reason)

Gate 1: enabled == True           (功能未禁用)
Gate 2: memory/ 目录有 .md 文件    (有记忆可整合)
Gate 3: mode != "plan"            (非计划模式)
Gate 4: 距上次整合 > 24 小时        (冷却期)
Gate 5: 距上次扫描 > 10 分钟        (节流间隔)
Gate 6: session_count >= 5        (足够的数据)
Gate 7: 无活跃锁文件               (无并发整合)
```

任一门控未通过 → 返回 `(False, "Gate N: 原因")`。

### 4 阶段整合流程

```python
PHASES = [
    "定向：扫描 MEMORY.md 索引以了解结构和分类",
    "收集：读取各个记忆文件以获取完整内容",
    "整合：合并相关记忆，移除过时条目",
    "修剪：强制 MEMORY.md 索引不超过 200 行",
]
```

### PID 锁机制

防止多个 Agent 会话同时整合：

```
ai_output/memory/.dream_lock
内容格式："{PID}:{timestamp}"
```

```python
def _acquire_lock(self) -> bool:
    if lock_file.exists():
        pid, timestamp = parse(lock_file)
        if time.time() - timestamp > 3600:   # 锁过期（1小时）
            unlink()                          # 强制移除
        elif os.kill(pid, 0) succeeds:        # PID 仍在运行
            return False                      # 锁有效
        else:
            unlink()                          # PID 已终止，移除
    
    # 创建新锁
    lock_file.write(f"{os.getpid()}:{time.time()}")
    return True
```

### 整合生命周期

```
Agent 会话启动
    │
    ▼
dream.session_count += 1
    │
    ▼ (满足条件时)
    │
dream.consolidate()
    │
    ├── should_consolidate() → 7 重门控
    │
    ├── 4 阶段流程执行
    │   (教学版本仅打印阶段描述，完整版会调用 LLM 做实际合并)
    │
    ├── last_consolidation_time = now
    │
    └── _release_lock()
```

### 配置常量

| 常量 | 值 | 含义 |
|------|-----|------|
| `COOLDOWN_SECONDS` | 86400 (24h) | 两次整合最小间隔 |
| `SCAN_THROTTLE_SECONDS` | 600 (10min) | 两次扫描检查最小间隔 |
| `MIN_SESSION_COUNT` | 5 | 触发整合所需的最少会话数 |
| `LOCK_STATE_SECONDS` | 3600 (1h) | PID 锁过期时间 |
| `DEDUP_THRESHOLD` | 0.8 | MinHash 相似度 > 此值视为重复 |
| `MERGE_THRESHOLD` | 0.6 | 相似度 > 此值则合并内容 |
| `DECAY_DAYS` | 60 | 衰减半衰期（天） |
| `MAX_FRAGMENTS_PER_SESSION` | 20 | 单次会话最多提取的片段数 |

## 四、consolidate_session — 5 步增量消化管道

> 会话结束时由 server.py 后台线程触发，不依赖 7 门控检查。

```python
def consolidate_session(self, messages, memory_manager, session_id="") -> ConsolidationReport:
    """会话结束时整合 — 增量消化管道。"""
```

### 5 步管道

```
对话历史 (messages)
    │
    ▼ Step 1: 提取片段 (_extract_fragments)
    │  三种来源:
    │  ① 用户显式反馈（纠正/偏好）→ feedback
    │  ② 项目上下文（技术决策/架构）→ project
    │  ③ 工具调用模式（重复序列）→ skill_learned
    │
    ▼ Step 2: 结构化分类
    │  按 type 字段过滤有效片段
    │  类型: user / feedback / project / mistake / skill_learned
    │
    ▼ Step 3: 去重 + 合并 (_process_fragment)
    │  MinHash 相似度 > 0.8 → 合并到已有记忆
    │  相似度 > 0.6 → 追加内容
    │  无匹配 → 保存为新记忆
    │
    ▼ Step 4: 链接检测 (_detect_links)
    │  keyword overlap → 记忆间关联
    │
    ▼ Step 5: 衰减 (_decay_memories)
       60 天未访问 → importance 降低
```

### ConsolidationReport

```python
@dataclass
class ConsolidationReport:
    extracted: int = 0      # 提取的片段数
    classified: int = 0     # 有效分类片段数
    saved_new: int = 0      # 新增记忆数
    merged: int = 0         # 合并到已有记忆数
    linked: int = 0         # 检测到的关联数
    decayed: int = 0        # 衰减的记忆数
    details: list[str] = field(default_factory=list)
```

## 五、会话结束钩子（server.py）

WebSocket 断开连接时，在 `finally` 块中启动后台线程执行完整的记忆消化 + 技能进化闭环。

```python
# server.py WebSocket finally block
_session_messages = list(agent.history)  # 复制对话历史
_session_id = agent.current_session_id or "unknown"

def _session_end_digest():
    """后台执行：记忆消化 + 技能进化。"""
    mm = MemoryManager()
    mm.load_all()

    # 1. 增量消化管道
    consolidator = DreamConsolidator()
    report = consolidator.consolidate_session(
        messages=_session_messages,
        memory_manager=mm,
        session_id=_session_id,
    )

    # 2. 重新加载记忆（消化后可能有新增）
    mm.load_all()

    # 3. 技能进化
    evo_result = SKILL_REGISTRY.evolve_skills_from_memories(mm)

threading.Thread(
    target=_session_end_digest,
    daemon=True,
    name="session-end-digest",
).start()
```

**关键设计**：
- `daemon=True`：不阻塞 WebSocket 断开流程
- `list(agent.history)`：在线程启动前复制，避免线程访问时 history 已被清理
- 异常在线程内捕获，不会影响主流程

## 七、ThreeLayerMemory — 三层记忆统一接口

> 源码：`core/utils/memory_manager.py` （新增，~609行，2026-06-22）

### 三层架构

```
                    ┌─ 短期记忆 ─── Agent messages 列表（已有）
                    │
ThreeLayerMemory ────├─ 压缩层 ───── ContextCompressor 封装
  (统一接口)          │               三级策略：micro → persist → compact
                    │
                    └─ 长期记忆 ─── 双后端：
                                    ├── Markdown 文件（已有 memory.py）
                                    ├── SQLite FTS5（memories 表 + memory_links 表）
                                    └── 用户画像（UserProfile 片段内嵌）
```

### 核心 API

```python
class ThreeLayerMemory:
    def __init__(self, db_path: Path = None):
        self.markdown_mem = MemoryManager()        # 复用现有
        self.fts: SQLiteFTS5                        # 新增 FTS5 全文检索
        self.compressor = ContextCompressor()       # 从 context_budget.py 提取
        self.user_profile = UserProfile()           # 新增 用户画像

    def recall(self, query: str, top_k: int = 3) -> RecallResult:
        """4 信号加权统一检索接口
        
        Signal 1: 直接引用 x3.0 — 查询中明确提到的实体
        Signal 2: 来源重叠 x4.0 — 与当前上下文来自同一对话/项目
        Signal 3: 图距离 x1.5 — Adamic-Adar，通过 memory_links 表
        Signal 4: 类型亲和 x1.0 — 同类型记忆优先
        
        最终加权：score x importance x time_decay（30天半衰期）
        """

    def store(self, name: str, content: str, mem_type: str, description: str = "") -> bool:
        """Markdown + FTS5 双写入，保证一致性"""

    def consolidate_session(self, messages: list, session_id: str = "") -> ConsolidationReport:
        """5 步增量消化管道 — 会话结束时由 server.py 后台线程触发"""
```

### RecallResult

```python
@dataclass

    memories: list[dict]     # FTS5 + Markdown 检索结果
    profile_facts: list[str] # 相关用户画像片段
```

### SQLite FTS5 存储结构

```sql
-- 记忆表
CREATE TABLE memories (
    id TEXT PRIMARY KEY,
    name TEXT,
    type TEXT,
    content TEXT,
    importance REAL DEFAULT 1.0,
    access_count INTEGER DEFAULT 0,
    created_at REAL,
    last_accessed REAL,
    source TEXT DEFAULT 'markdown'
);

-- FTS5 全文检索虚拟表
CREATE VIRTUAL TABLE memories_fts USING fts5(
    name, content,
    tokenize='unicode61',
    content='memories', content_rowid='rowid'
);

-- 记忆关联表
CREATE TABLE memory_links (
    source_id TEXT,
    target_id TEXT,
    weight REAL DEFAULT 1.0,
    relation TEXT DEFAULT 'related'
);
```

**内置 FTS5 中文分词**：使用 `unicode61` tokenizer + 预分词层，支持 CJK 文本检索。

## 八、UserProfile — 渐进式用户画像

> 源码：`core/utils/user_profile.py` （新增，~250行，2026-06-22）

### 设计理念

正则规则提取，零 LLM 调用成本，从对话流中渐进建立用户标签。

### 画像类别

| 类别 | 示例 | 提取规则 |
|------|------|----------|
| `preference` | “不要用 mock” “尽量不要注释” | 否定居系词 + 空篟 + 动词 |
| `style` | “回复简洁一些” “小标题分段” | 风格关键词匹配 |
| `background` | “我是做机器学习的” | 项目/职业背景关键词 |
| `habit` | “第一个先写测试” | 工作流程模式 |

### API

```python
@dataclass
class ProfileFact:
    category: str    # preference / style / background / habit
    content: str     # 画像内容
    confidence: float = 1.0
    source_turn: int = 0

class UserProfile:
    def extract(self, messages: list) -> list[ProfileFact]:
        """正则规则扫描对话，提取用户画像片段"""

    def get_relevant(self, query: str) -> list[str]:
        """检索与当前查询相关的画像片段，返回可直接嵌入提示词的字符串列表"""

    def update(self, facts: list[ProfileFact]) -> None:
        """追加/合并画像片段，第一条同类型覆盖旧条"""

    def save(self, path: Path) -> None:
        """持久化到 ai_configuration/.memory/profile/ 目录"""

    def load(self, path: Path) -> None:
        """YAML frontmatter 正则解析，不依赖 pyyaml"""
```
