# Agent 阶段契约

本契约定义数字人对话与 Agent 执行各阶段的职责。人设只影响表达方式；阶段、工具权限和执行结果由系统逻辑决定。

| 阶段 | 输入 | 职责 | 权限与输出 |
|---|---|---|---|
| Phase 1 路由 | 用户消息、当前轮附带的截图、实时信息 | 选择闲聊、知识回答、澄清或委派；只作即时回应 | 不调用工具、不声称任务已完成；末尾输出且只输出一个独立动作标记 `[CHAT]`、`[ANSWER]`、`[CLARIFY]` 或 `[EXECUTE]` |
| Phase 2 用户任务 | 原始用户请求、工作区与可用工具 | 完成 Phase 1 委派的任务 | 依照用户任务和工具权限执行；如缺少关键目标/参数则澄清；如实报告工具结果 |
| 执行中旁白 | 新用户消息、当前任务状态 | 回答进度问题，识别取消或变更意图 | 不执行新任务；只发出 `[CHANGE_DETECTED]` 信号交给调度层 |
| 自主认知决策 | 对话、记忆、环境摘要 | 选择继续、暂停、表达、记忆或提出行动意图 | `act` 仅产生候选意图，不代表已获写入权限 |
| 自主行动 | 候选意图、工作区 | 进行低风险自主探索 | 默认 `autonomous_readonly`；允许读取与白名单查询，禁止文件写入/删除、消息发送和桌面操作 |

## 执行路由

- 若答案依赖访问当前工作区、网络、运行环境，或需要执行真实操作，使用 `[EXECUTE]`。
- 若只根据用户已提供材料或通用知识推理，不需要外部验证，使用 `[ANSWER]`。
- 目标或关键参数不明确时，使用 `[CLARIFY]`，不猜测执行范围。
- 当前消息附带的截图可直接用于回答图中可见内容；它不代表可见后续实时画面。获取新截图、点击、输入或操作桌面必须走 `[EXECUTE]`。
- Phase 1 的标记只能出现在最后一个非空行，且只能有一个。服务端只认精确标记行。

## 自主行动与文件修改

- 自主 `act` 默认只读；即使候选意图写着“创建”“修复”或“整理”，执行器也只能调查并给建议。
- 用户明确提出的文件修改进入 Phase 2 用户任务流程，并受常规工具权限策略约束。
- 只读限制在 ToolDispatcher 执行前强制检查，不依赖模型遵守提示词；只读自主范围不切换共享权限门的全局模式。
